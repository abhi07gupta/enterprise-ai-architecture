# Architecture principles

## 1. Start with the enterprise decision
The unit of architecture is not the model. It is the decision or workflow the capability must improve.

## 2. Make boundaries explicit
Name what the AI system owns, what surrounding systems own, and where a human remains accountable.

## 3. Treat context as a first-class architectural concern
Enterprise reasoning depends on meaning, provenance, policy and relationships — not only raw text or records.

## 4. Match reasoning complexity to the problem
Use deterministic logic when it is sufficient. Use ML, retrieval, generation or agentic reasoning only when each adds justified capability.

## 5. Design trust into the system
Validation, human oversight, policy enforcement, failure containment and auditability should be part of the architecture.

## 6. Prefer replaceable components
Models and vendor services change quickly. Keep stable contracts around data, knowledge, evaluation, integration and workflow.

## 7. Architecture includes operability
Ownership, observability, cost, change management and incident handling must be designed before production.

## 8. Optimize for organizational learning
Capture decisions, evidence and reusable patterns so the next AI initiative starts from a stronger baseline.
